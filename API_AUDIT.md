# API contract audit

## Result and limits

Every outbound request family implemented in this repository was inventoried. Confirmed request, authentication, response-handling, and account-scope defects were repaired. **This is not a certification of exact official-client emulation.** Undocumented endpoints vary with account, experiment, region, trust tokens, and device. Compatibility with an extractor or a successful HTTP response does not establish native-client fidelity.

Evidence below distinguishes current public-service observations, captured official WEB traffic, deterministic regressions, and paths still requiring an authenticated account or Apple/device runtime. No real account credentials were sent to external compilation services, and no authenticated personal-account mutations were attempted.

## Complete outbound inventory

All InnerTube calls use `https://www.youtube.com/youtubei/v1/` through `InnertubeClient`. The shared builder owns profile identity, locale, visitor consistency, authentication, and account routing; endpoint consumers retain opaque server commands/tokens.

## Platform identity is a compatibility contract

`ClientProfiles.json` keeps the maintained compatibility pins rather than guessing newer versions. WEB uses a live bootstrap version when available; that WEB version must not leak into MWEB, embedded, VISIONOS, or TV identities. The captured current WEB version was `2.20261030.02.00`; another official bootstrap returned a complete canary-suffixed version, which is now preserved instead of truncated.

The configured identities are WEB/1, MWEB/2, WEB_EMBEDDED_PLAYER/56, VISIONOS/101, and TVHTML5/7, with separate Safari WEB compatibility. Their OS/device/UA pins are not physical-device attestation. Native mobile, TV, and Vision Pro packet parity has not been established. Current anonymous browser/TV fallbacks can be trust-gated even when their request identities are internally consistent.

The embedded fallback is explicitly compatibility-only. Maintained implementations use different third-party contexts, while the observed official standalone embed bootstrap used encrypted embedded-player context. There is insufficient evidence to invent a Reddit/Google embedding origin, replace encrypted fields, or assert the existing fallback is exact.

## Intentional differences and unresolved prerequisites

- Ad, remarketing, QoE, `log_event`, and fabricated device/trust-token traffic were not added to imitate the full browser request stream.
- History registers actual playback starts. It does not implement account watchtime, completed-watch status, or remote resume synchronization. Local resume progress remains separate. Observing native watchtime calls does not prove that inventing watch ranges is necessary for registration.
- Native read-only chat uses a verified direct initial POST instead of loading/executing the browser's chat iframe. Replay, sending messages, moderation controls, ticker/banner cards, and complete browser rendering parity are not implemented. Missing/nonpositive polling delays retain a paced fallback; positive server delays are not arbitrarily clamped.
- The scope-free cookie representation cannot reproduce a browser's complete domain/path jar. Imports are therefore restricted to cookies applicable to the actual API target, and credential-bearing cross-origin redirects fail closed rather than attempting browser SSO behavior.
- Fresh authenticated account and brand-channel traffic is needed to verify positive rating/subscription/playlist changes, account menu variants, history persistence, routing/signing variants, and XSRF lifetime. No real credentials or authenticated mutations were used for this audit.
- Full Apple SDK compilation, visual UI validation, embedded sign-in, sustained media decoding/DVR, background playback, PiP, and AirPlay need Xcode and real/simulated Apple hardware. A successful public HLS fetch is not proof of those behaviors.

## Verification actually performed

All **184 core tests in 22 suites** passed in five dependency-complete isolated Swift 6.2 executions, using the repository's test sources and fixture bytes. The external `swift-crypto` package was unavailable there, so SHA-1/SHA-256 were supplied by actual OpenSSL 3 primitives with known digest checks. This was not a local `swift test` or an iOS build. Oversized single-executable requests exceeded the compilation service's processing deadline; splitting the suite preserved all test coverage.

Production request builders generated the anonymous requests sent to public endpoints; actual returned payloads were then processed by the production parsers. Controlled native HTTP smokes exercised cancellation, redirects, authenticated history POST/form handling, and feed retrieval. Additional smokes used the actual FeedModel and sign-in cookie-capture source with only framework/environment adapters to exercise account changes, pagination failures, explicit reload, and cookie selection. All ten changed app source files passed Swift syntax parsing; that does not replace Apple SDK typechecking or visual checks.
